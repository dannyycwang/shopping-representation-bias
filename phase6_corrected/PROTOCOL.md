## Value path and four fixed scoring architectures

Every method returns normalize(.5*non_attribute + .5*normalize(sum_i softmax(scores)_i*h_i)), where h_i is the unchanged frozen 768-D BGE value. Only scalar scoring weights are learned. There is no output value projection, embedding residual, positional input, learned product mixing or extra candidate slot. Empty attributes produce zero attribute vector and the normalized non-attribute vector.

C1: phi(h)=GELU(Linear128(GELU(Linear768→128(h)))); c=masked mean(phi(h)); scores=Linear128→1(Tanh(Linear896→128(concat(h,c)))). No explicit field identity. C2: Linear768→128, the existing one four-head self-attention/residual/LayerNorm/feed-forward block, then Linear128→1 scores. No PMA output, positional encoding or contextual values in final pooling. C3 is C2 with a learned 128-D native-key embedding added before the attention block. C4: project h to128, concatenate cos(theta_key),sin(theta_key); two128-D GELU layers; masked mean global context; a shared 256→128→1 Tanh scorer over local/global states. Angles are trainable, initialized evenly around a circle in frozen lexical field-ID order. This order is a parameter-label convention, never the incoming atom position. C4 is exploratory; its comparison with C3 changes more than the geometry and is not a causal isolation of circularity.

Field vocabulary uses raw native keys of products judged for TRAIN query IDs across all three labels. No dev/test query judgments define the vocabulary. ID0 is explicit UNK. Every duplicate occurrence remains. All final scalar scoring layers have exactly zero initial weight/bias, giving uniform nonpadding weights and Set-Mean geometry. No historical learned model initializes the corrected parameters. Shared C2/C3 modules initialize identically for a given seed before identity parameters are allocated.

## Graded query-balanced training

Audit every training qrel before training; retain per-query counts and eligibility. Allowed relations and loss multipliers are Exact>Irrelevant (1), Exact>Partial (.5), Partial>Irrelevant (.5). A query with no strict judged relation is excluded with its label counts. No unjudged/pseudo-negative or cross-query relevance inference is permitted.

Each epoch has64 independently shuffled complete cycles over all eligible queries. Therefore every eligible query receives exactly64 presentations/epoch (max/min=1). Within a query, its available relations cycle in a seed-shuffled order. Independently seed-shuffled higher/lower product pools both rotate across presentations and epochs. The planned20-epoch schedules for seeds42/43/44 are saved before training and identical across architectures and learning rates for a given seed. Actual per-query and relation presentations, unique products/comparisons, repeated products, and all sampled comparisons are retained. A batch is16 consecutive query-balanced presentations; at most a cycle boundary can repeat a query inside a batch. This equalizes presentation count, while the required relation weights still change weighted gradient exposure.

Loss = mean(weight*softplus((q·v(lower)-q·v(higher))/.05)). BGE and queries are frozen. AdamW, weight_decay=.01, global clip=1, lr in {1e-4,3e-5}, maximum20 epochs, patience4. All four architectures run all three seeds from the start for both learning rates. No broad tuning or secondary multi-negative diagnostic follows the outcomes.

## Neutral checks and common selection across seeds

Freeze config and all experiment source/data hashes before initialization measurements. Check each architecture at epoch0 against an independently computed equal-weight original-value expression (max L2≤1e-5), frozen Set-Mean development Recall@100 (absolute discrepancy≤.05 percentage points), and actual input permutations. No held-out epoch0 metric is read until selection is locked. During training retain epoch0 metrics for every seed/config, but epoch0 is never a selectable checkpoint and does not count toward patience.

For each architecture/LR, train its three seeds together by epoch. Compute the arithmetic mean of their development Exact Recall@100; tie-break with mean graded cNDCG@10 (strict improvement tolerance1e-12). The first eligible checkpoint is epoch1. Save all three at a common improving epoch. Stop the group after4 nonimproving epochs, at most20. Choose the architecture's single LR and single epoch from the best mean across the two LR groups; ties favor earlier epoch then lower LR. Do not select a different configuration or epoch separately for each seed. The best learned architecture is chosen by these mean dev metrics, then fewer trainable parameters and C1/C2/C3/C4 order. Preserve the unselected LR's three checkpoints, every epoch curve, step gradients and loss. Lock every choice before corrected held-out evaluation.
