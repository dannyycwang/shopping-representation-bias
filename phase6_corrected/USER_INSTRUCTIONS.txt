PHASE VI — CORRECTED STRUCTURAL PERMUTATION-INVARIANT RETRIEVAL

IMPORTANT
=========

This is a CLEAN RERUN of Phase VI under a corrected experimental design.

It is NOT Phase VI-B, Phase VI-C, or a new architecture-search phase.

The previous Phase VI / VI-B results must remain archived as pilot evidence,
but they are NOT the primary evidence for the corrected Phase VI.

The corrected design explicitly removes two known confounds:

1. learned invariant models must NOT relearn a new 768-dimensional retrieval
   space from a randomly initialized output projection;

2. learned residual vectors must NOT be able to grow arbitrarily and dominate
   an existing pretrained representation.

Instead, every learned architecture may ONLY determine how existing frozen BGE
field value vectors are combined.

The final product representation must remain directly inside the pretrained
BGE embedding geometry.

1. SCIENTIFIC QUESTION
==================================================

The central question is:

    Can we obtain exact permutation invariance across structured product
    attributes while preserving retrieval-relevant information?

We specifically test whether richer cross-field reasoning improves over simple
invariant aggregation WITHOUT requiring the model to reconstruct the BGE
retrieval space.

The desired representation must satisfy:

    permutation invariance across attribute fields

while preserving:

    sequence semantics inside each field
    +
    pretrained BGE field representations
    +
    useful interactions among fields.

==================================================
4. CORE DESIGN PRINCIPLE — VALUE-PRESERVING INVARIANCE
==================================================

For every product attribute atom:

    a_i

obtain the existing frozen BGE embedding:

    h_i = E_BGE(a_i)

h_i must NEVER be replaced by a randomly learned 768-dimensional product
vector.

The learned architecture may compute:

    contextual information
    attention weights
    field gates
    field importance

but the final attribute vector must always be:

    v_attr =
        normalize(
            sum_i w_i * h_i
        )

where:

    w_i >= 0
    sum_i w_i = 1

Use softmax weights.

This guarantees that the learned representation remains a weighted combination
of pretrained BGE field values.

No unconstrained learned 768-dimensional output projection is allowed.

No learned residual may be added directly to the final product embedding.

==================================================
5. FINAL PRODUCT VECTOR
==================================================

Use exactly the same combination rule as the existing Set-Mean and
Set-Attention baselines:

    v_product =
        normalize(
            0.5 * v_non_attribute
            +
            0.5 * v_attr
        )

Do NOT learn the 0.5 / 0.5 mixing coefficient in the primary experiment.

This ensures architectural comparisons isolate ATTRIBUTE AGGREGATION.

Final dimensionality:

    768

Vectors/product:

    1

Candidate budget:
    unchanged.

==================================================
6. METHOD C0 — EXISTING SET-ATTENTION
==================================================

Retain the existing Set-Attention as architectural baseline.

It computes each field's score independently:

    s_i = MLP(h_i)

    w_i = softmax_i(s_i)

    v_attr = normalize(sum_i w_i h_i)

There is no explicit field-to-field context before scoring.

This baseline answers:

    Is independent learned field weighting sufficient?

==================================================
7. METHOD C1 — CONTEXTUAL DEEPSETS ATTENTION
==================================================

Goal:

Allow each field's importance to depend on the OTHER fields while preserving
the original BGE value vectors.

For each field:

    u_i = phi(h_i)

Compute global permutation-invariant context:

    c = mean_i u_i

Then compute contextual score:

    s_i = psi(
        concat(
            h_i,
            c
        )
    )

Weights:

    w_i = softmax_i(s_i)

Final attribute vector:

    v_attr = normalize(sum_i w_i h_i)

IMPORTANT:

The learned network outputs ONLY scalar weights.

It does NOT output replacement value vectors.

This method is permutation invariant because:

    c

is symmetric and each field uses the same scoring function.

Recommended hidden dimension:

    128

Do not architecture-search this aggressively.

==================================================
8. METHOD C2 — VALUE-PRESERVING SET TRANSFORMER
==================================================

Goal:

Model explicit field-to-field interactions before assigning weights.

Input:

    h_1, ..., h_m

Project ONLY for attention computation:

    x_i = P(h_i)

Use:

    one multi-head self-attention block
    4 heads
    hidden dimension 128
    residual connection
    layer normalization
    feed-forward block

NO positional encoding.

This produces contextual states:

    c_i

Then compute:

    s_i = linear(c_i)

Weights:

    w_i = softmax_i(s_i)

CRITICAL:

Final values are NOT c_i.

Final values remain the ORIGINAL frozen BGE vectors:

    v_attr =
        normalize(
            sum_i w_i * h_i
        )

This is the key correction from the previous Phase VI.

The Set Transformer learns WHERE TO ATTEND,
not a new retrieval embedding space.

==================================================
9. METHOD C3 — SET TRANSFORMER + FIELD IDENTITY
==================================================

Same architecture as C2.

Field identity may affect the ATTENTION/SCORING network only.

For field key f_i:

    e_i = learned_field_embedding(f_i)

Attention input:

    x_i =
        P(h_i)
        +
        e_i

The value vectors used in the final product representation remain:

    h_i

NOT:

    x_i
    or
    c_i.

Unknown field keys:

    explicit UNK field ID.

Duplicate keys:
    preserve all occurrences.

Do not collapse duplicate atoms or duplicate field names.

This comparison isolates:

    contextual interaction alone
    versus
    contextual interaction + schema identity.

==================================================
10. METHOD C4 — CIRCULAR FIELD-IDENTITY ATTENTION
==================================================

This is exploratory but retained because it was part of the original Phase VI
question.

Do NOT serialize fields into a ring.

Do NOT use ABCDA / BCDAB sequence tricks.

Instead, represent FIELD IDENTITY geometrically.

For each field f:

    theta_f

and:

    e_f =
        [cos(theta_f), sin(theta_f)]

Combine only inside the scoring network:

    x_i =
        concat(
            P(h_i),
            cos(theta_fi),
            sin(theta_fi)
        )

Use a small shared network and symmetric global context:

    u_i = phi(x_i)
    c = mean_i u_i
    s_i = psi(concat(u_i, c))

Then:

    w_i = softmax_i(s_i)

Final attribute vector:

    v_attr =
        normalize(
            sum_i w_i * h_i
        )

Again:

Circular geometry determines WEIGHTS only.

It must never replace the BGE field values.

Angles may be trainable but must be tied to FIELD IDENTITY,
not serialization position.

==================================================
11. WHY THIS DESIGN IS DIFFERENT
==================================================

Every new architecture is now a contextual weighting mechanism over frozen
pretrained values.

The comparison is therefore:

Set-Mean:
    equal weights

Set-Attention:
    independent learned weights

DeepSets:
    globally contextual learned weights

Set Transformer:
    pairwise contextual learned weights

Set Transformer + Field-ID:
    pairwise contextual weights with schema information

Circular:
    contextual weights with geometric schema identity

All methods:

    use the SAME frozen BGE field values
    produce ONE product vector
    have ZERO positional input
    are permutation invariant.

This removes the prior random-output-space confound.

==================================================
16. TRAINING OBJECTIVE
==================================================

For query q, higher-relevance product p+, lower-relevance product p-:

    s+ = q · v(p+)
    s- = q · v(p-)

Loss:

    L =
        weight *
        softplus(
            (s- - s+) / tau
        )

Use:

    tau = 0.05

The query embedding remains frozen.

BGE remains frozen.

Only field-weighting architecture parameters train.
