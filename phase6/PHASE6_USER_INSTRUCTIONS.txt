PHASE VI — STRUCTURAL PERMUTATION-INVARIANT PRODUCT REPRESENTATIONS

Important scientific constraint
================================
This phase is allowed to fail.

The purpose is to determine whether structural permutation-invariant
architectures can preserve more retrieval effectiveness than the existing
Set-Mean and Set-Attention controls.

Do NOT manufacture a positive result.
Do NOT tune on the test set.
Do NOT redesign the full paper yet.
Retain all negative results.

==================================================
0. BACKGROUND AND MOTIVATION
==================================================

Phase V established the following on the existing raw WANDS/BGE track:

Original:
    Recall@100 = 63.620
    VI@20      = 11.932

Canonical:
    Recall@100 = 63.237
    VI@20      = 0.000

Set-Mean:
    Recall@100 = 61.820
    VI@20      = 0.000

Set-Attention:
    Recall@100 = 62.173
    VI@20      = 0.000

The existing Set-Attention implementation is NOT a full Set Transformer.

Current Set-Attention:
    frozen BGE field embedding
    -> 768 -> 128 -> 1 scorer
    -> scalar weight per field
    -> weighted field mean
    -> mix with non-attribute vector

It does not perform explicit attribute-to-attribute self-attention.

Interpretation of Phase V:
- exact invariance is easy;
- simple averaging loses retrieval-relevant information;
- learned scalar field weighting recovers only a small amount;
- the remaining question is whether explicitly modeling cross-field
  interactions can recover effectiveness while keeping exact permutation
  invariance.

Phase VI therefore focuses on structural invariant encoders.

==================================================
2. COMMON REPRESENTATION PRINCIPLE
==================================================

For a product p with attribute atoms:

    A(p) = {a_1, ..., a_m}

encode each complete attribute atom independently:

    h_i = E_attr(a_i)

where E_attr is the existing frozen BGE field encoder.

Important:

- preserve token order WITHIN each attribute atom;
- remove dependence on order BETWEEN attribute atoms;
- do not insert global serialization-position embeddings;
- do not reorder tokens inside an attribute;
- do not generate or rewrite product facts.

The desired property is:

    f(h_1, ..., h_m)
    =
    f(h_pi(1), ..., h_pi(m))

for any permutation pi.

We want:

    permutation invariance across fields
    +
    semantic sensitivity within fields
    +
    useful interactions across fields.

==================================================
3. METHOD S1 — TRUE SET TRANSFORMER
==================================================

Goal
----
Test whether explicit self-attention across unordered attribute embeddings
recovers retrieval effectiveness lost by Set-Mean / Set-Attention.

Architecture
------------

Input:

    H = [h_1, ..., h_m]

Use a small permutation-equivariant self-attention encoder.

Preferred initial architecture:

    1 x Multi-Head Self-Attention block
    hidden dimension: 128 or 256
    heads: 4
    residual connection
    layer normalization
    small feed-forward block

No positional encoding.

The attention layer must operate over the SET of attribute embeddings.

Then use permutation-invariant pooling.

Preferred pooling order:

Option A:
    PMA-style learned seed pooling

or, if simpler:

Option B:
    attention pooling with one learned query vector

Avoid ordinary mean pooling as the final primary method unless required as a
debug baseline.

Output:

    v_attr(p)

Normalize using the same convention as existing methods.

Combine with the existing non-attribute product representation using the same
mixing rule as Set-Mean / Set-Attention so that the architecture comparison is
fair.

Primary S1 should change only the attribute aggregator.

Frozen BGE in initial screening.

==================================================
4. METHOD S2 — SET TRANSFORMER + FIELD-ID EMBEDDING
==================================================

Goal
----
Test whether explicit field identity helps preserve semantics that may be lost
when attributes are treated only as anonymous content vectors.

Motivation:

Serialization position should not identify a field.

Instead:

    identity = field meaning/schema
    position != serialization index

For each attribute:

    h_i = E_attr(a_i)

Construct a learned field identity embedding:

    e_f = embedding(field_name)

Then:

    x_i = projection(h_i) + e_f

Feed:

    {x_1, ..., x_m}

into the same Set Transformer architecture as S1.

Important:
- field ID is determined from the actual attribute key/schema;
- field identity must remain the same under reorder;
- do not encode incoming field position;
- unknown/unseen keys must use an explicit UNK-field embedding;
- duplicate keys must not be silently collapsed.

Do NOT manually specify semantic relations among fields.

This method should learn whether:
    color
    material
    dimensions
    compatibility
    ...

need distinct schema identities while remaining globally unordered.

Ablation:
    S1 = no field ID
    S2 = learned field ID

This is the most important architectural comparison in Phase VI.

==================================================
5. METHOD S3 — CIRCULAR SCHEMA PROJECTION
==================================================

Goal
----
Explore whether field identity can be projected into a fixed geometric schema
space rather than represented using arbitrary serialization positions.

IMPORTANT:
This is NOT simple ring serialization.

Do NOT implement:

    ABCDA
    BCDAB

as the main method, because cyclic-shift invariance does not imply arbitrary
permutation invariance.

Instead, implement an order-independent circular FIELD-IDENTITY projection.

For each unique field identity f, assign or learn an angular embedding:

    theta_f

Represent field identity using:

    c_f = [cos(theta_f), sin(theta_f)]

Then combine content and field identity.

Recommended formulation:

    h_i = E_attr(a_i)

    g_i = MLP(
        concat(
            projection(h_i),
            cos(theta_fi),
            sin(theta_fi)
        )
    )

Aggregate with a symmetric operator.

Primary version:

    v_attr(p) = sum_i g_i
or
    v_attr(p) = mean_i g_i

followed by an output MLP.

Because summation/mean is symmetric, arbitrary input reorder must not change
the output.

The circular coordinates must represent FIELD IDENTITY, not input position.

Test two variants only if cheap:

S3-fixed:
    deterministic evenly spaced field angles based on a stable global field
    vocabulary ordering

S3-learned:
    theta_f is trainable

If implementing both substantially increases work, prioritize S3-learned.

Important interpretation:
The circular geometry is exploratory.
Do not claim that circular topology is inherently correct unless supported by
results.

6. OPTIONAL METHOD S4 — FIELD-PROJECTION DEEPSETS
==================================================

Only implement this if it is essentially free once S2/S3 infrastructure exists.

Purpose:
Separate the value of Set Transformer attention from a simpler learned
permutation-invariant projection.

For each field:

    z_i = phi(h_i, field_id_i)

Then:

    v_attr(p) = rho(sum_i z_i)

This is a learned DeepSets-style baseline.

This comparison is useful:

    Set-Mean
        vs
    Field-aware DeepSets
        vs
    Set Transformer
        vs
    Set Transformer + Field ID

Do NOT prioritize S4 over S1-S3.

==================================================
13. SUCCESS CRITERIA
==================================================

The main question is NOT whether VI reaches zero.

All structural invariant methods should have near-zero VI.

The real question is:

    Can we achieve invariance WITHOUT losing retrieval effectiveness?

STRONG SUCCESS
--------------

A method is a strong success if:

    VI@20 approximately 0

AND

    Recall@100 >= Canonical

preferably:

    Recall@100 >= Original

AND

    Robust@100 >= Canonical

Particularly strong:

    Recall@100 >= 63.62
    VI@20 ~= 0

PROMISING
---------

A method is promising if:

    Recall@100 > Set-Attention

with clear paired improvement,
while preserving exact invariance.

Example:

    Recall@100 >= 62.8

would justify further confirmation even if it does not beat Canonical.

FAILURE
-------

A method is not successful if:

- VI=0 but Recall remains at or below Set-Mean;
- gains over Set-Attention are trivial;
- it requires materially larger inference/storage cost with no effectiveness gain;
- it only looks favorable on test but not development.
